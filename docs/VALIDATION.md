## 可重复执行的检查

```sh
# JAVA_HOME 指向 JDK 25；在 Linux amd64 上执行完整互通测试
make test
make package
python3 tools/check-docs.py
```

| 层次 | 覆盖内容 |
| --- | --- |
| 发布辅助脚本 | 标签格式、稳定/预发布判定、版本不匹配、附件白名单、校验和、草稿先上传后发布、失败重试、已公开版本不覆盖 |
| Go | format/vet、密码和会话、邀请码过期/次数、撤销、CSRF、不可变发布、通道回滚、JAR 识别与去重、Local/S3/OSS 适配 |
| Java | 清单验签与篡改、URL、扫描、计划、大小/哈希/超时、跨 origin 令牌剥离、同步事务、隔离恢复、多实例锁 |
| 版本一致性 | 服务端 version 输出、JAR 元数据、客户端内部版本、发布文件名 |
| 跨语言集成 | 启动临时 Go 服务，由真实 Java 客户端登记私密设备、固定公钥、获取清单、验签、下载、同步并验证撤销后拒绝访问 |
| 打包 | ELF64 amd64、版本一致、生产 JAR 含 Gson、SHA256SUMS |
| 文档 | README 与 docs 的相对链接有效，不展示调试图片 |

`make test` 设置 `MLD_SERVER_BINARY` 运行真实互通测试；单独执行 Gradle test 且未设置该变量时，此项会跳过。测试采用临时目录，不接触玩家游戏实例。

## 浏览器验收

先 `make server`，再执行：

```sh
node tools/ui-smoke.mjs
```

需要 Node 22+、Python 3、Chrome；可通过 `CHROME=/path/to/chrome` 指定浏览器。脚本使用本机端口 18775 / 18776、临时数据库和临时 Chrome 配置，不修改部署数据，结束后清理测试进程及临时目录。

覆盖登录失败与重试、空状态、创建私密服务器、上传 JAR、按名称选择 MOD、自选/禁止规则、依赖检查、封存启用、邀请码、设备登记/撤销、指南/设置、列表筛选、断网恢复、文本安全、桌面和 390px 布局、导航、CSP 和无外部资源请求。

## 游戏内验收步骤

在独立游戏目录中准备 Minecraft 26.2、Fabric Loader 0.19.5、Fabric API 0.155.2+26.2 和本项目 JAR：

1. 确认标题入口可打开，添加公开和私密测试服务器。
2. 检查环境与可选 MOD，核对缺少、额外、冲突和禁止规则。
3. 确认下载和安装，验证过程中失败不会留下半成品环境。
4. 变更完成后显示需要重启，重启再次检查为就绪。
5. 切换另一服务器配置，验证重新生成计划及未知文件确认。
6. 测试隔离恢复、未完成事务恢复和第二实例只读。

此前已在 Linux 图形环境实际验证标题入口、地址添加、真实 Fabric API 文件同步与重启后就绪。当前发布自动化不运行完整 Minecraft 图形验收，版本或游戏 API 变更后仍应手动执行。

## 验证边界

- S3 使用模拟 HTTP 接口验证，OSS 覆盖签名地址和对象键；未用真实云账号做 bucket 联调。
- 没有验证所有第三方 MOD 组合或 Windows/macOS 图形环境。
- 本地发布脚本测试使用模拟 GitHub CLI，不会真的创建远端 Release。实际 token 权限、GitHub Artifact 与 Release 上传要在目标仓库运行后确认。
- 文档检查不请求外部链接，也不检查标题锚点。
