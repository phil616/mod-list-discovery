# MOD 环境管家：服主入门指南

管理后台打开 `/admin/`，登录后在左下角“查看入门指南”或右上角“使用帮助”随时查阅内置说明。

## 你在管理什么

Minecraft 游戏服务器负责联机。本项目的管理服务负责保存 MOD 文件、搭配玩家环境并提供同步地址。这两个服务可以部署在一起，但用途不同。

玩家在 Mod List Discovery 中填写的是 `https://你的管理服务域名/地址名称`。这不是 Minecraft 多人游戏界面中的服务器 IP。

管理界面采用 Bootstrap 5.3.8 的样式和交互组件，所有文件内嵌在 Go 二进制中；无需 Node、外部 CDN 或联网加载字体。桌面使用侧边栏，窄屏使用左上角导航按钮。

## 第一次上线：四步完成

### 1. 创建服务器配置

在“我的服务器”点击“创建服务器”：

| 字段 | 怎么填 | 示例 |
| --- | --- | --- |
| 玩家看到的名称 | 用玩家熟悉的名字，可以用中文 | 朋友们的生存服 |
| 地址中的名称 | 1–64 个小写字母、数字或短横线，首位为字母或数字，创建后不可修改 | friends-survival |
| 访问方式 | 公开：知道地址即可使用；私密：必须先通过邀请码登记设备 | 私密 |
| 给玩家的介绍 | 选填，说明玩法或用途 | 周末轻量生存，需要 Fabric |

表单会预览生成的分享地址。此时尚未启用环境，先不要通知玩家同步。

### 2. 上传玩家需要的 MOD

在“MOD 文件库”点击“上传 MOD 文件”，选择 Fabric `.jar`。系统读取 `fabric.mod.json`，自动识别名称、版本、Mod ID 和适用环境，不会执行 JAR。相同内容的文件只保存一份。

也可使用“从下载链接导入”，填写可以直接下载 JAR 的 HTTPS 链接。MOD 介绍页或内网链接通常不能导入。默认文件上限为 512 MB，实际限制以部署配置为准。

只在游戏服务端运行的 MOD 不应发给玩家。搭配环境时，选择器会隐藏仅服务端 MOD 和同步客户端自身。需要的其他 MOD 依赖也应按实际情况上传。

**上传只保存文件，还不会影响玩家。**

### 3. 搭配并封存环境版本

在“环境版本”点击“创建环境版本”，选择服务器，起名如“首次开放”或“国庆更新”。创建后进入草稿详情。

点击“添加 MOD 或规则”，根据需要选择：

| 规则 | 效果 | 需要填写 |
| --- | --- | --- |
| 必须安装 | 玩家同步时安装指定文件 | 从文件库按名称、版本选择 |
| 玩家自选 | 玩家决定是否安装 | 选择文件，以及首次是否默认勾选 |
| 禁止安装 | 检测并提示处理不允许的 MOD | Mod ID、可选显示名称和版本范围 |

同一个 Mod ID 再次添加会替换当前草稿中的规则。禁止规则不需要上传文件；其默认版本范围 `*` 表示所有版本。

通常保留高级运行环境设置：Minecraft `26.2`、Fabric Loader `>=0.19.0`、Java `>=25`、同步客户端最低版本 `0.1.0`。这些是对玩家运行环境的要求，不会替玩家安装游戏、Java 或 Loader。

点击“检查依赖”，处理冲突和版本不匹配。缺少依赖的提示需要结合 MOD 说明检查：依赖可能在 JAR 内嵌，也可能需要另外安装。这个检查不等于完整 Fabric 求解或实际启动测试；封存时还会检查文件和运行环境字段。

确认配置后点击“完成配置并封存”。**封存后的内容不能再改，但不会自动分发给玩家。**

### 4. 启用给玩家并分享地址

在已封存的环境版本中点击“启用给玩家”，按名称选择这一版。通常保持默认正式版 `stable`，无需填写或记忆版本编号。

启用完成后回到服务器详情，从“分享给玩家”复制地址。私密服务器还要在“玩家设备与邀请”创建邀请码。

玩家需要：

1. 安装匹配的 Minecraft、Fabric Loader、Fabric API 和 Mod List Discovery 客户端。
2. 启动游戏，在标题界面打开 Mod List Discovery，添加服主提供的完整地址。
3. 私密服务器使用“设备授权”输入邀请码。
4. 检查环境，选择可选 MOD，查看同步计划并按提示确认；本地未知冲突文件需要单独确认处理。
5. 同步后重启，再次检查环境就绪，然后使用游戏服务器地址联机。

MOD 不能在游戏运行时热加载。启用新版本也不会强制改变正在运行的游戏。

## 日常更新和回退

更新 MOD 时先上传新文件，创建新的环境版本草稿并重新搭配，检查、封存后再启用。旧版保留不变，便于追溯。

需要回退时，在服务器详情点击“选择已封存版本并启用”，选回之前的一版。玩家下次检查、同步并重启后使用所选环境。回退 MOD 环境不等于恢复世界存档。

文件被草稿或已封存版本引用时不能删除；草稿引用可以先移除。已有封存版本的服务器不能删除。

## 邀请码与玩家设备

公开服务器通常无需邀请码。私密服务器可以生成限制次数和有效期的邀请码：一个设备登记消耗一次使用机会；到期或用完后不能再登记。

完整邀请码只在创建成功时显示，请立即复制。关闭后列表只显示有效期和使用情况，不显示原始邀请码。可直接复制包含地址、邀请码和步骤的完整说明发给玩家。

邀请码登记成功后，设备使用独立凭证继续访问：

- 撤销邀请码：阻止之后用这个码登记，已有设备仍可访问。
- 撤销设备授权：这个设备不能继续访问私密清单，需要新邀请码重新登记。
- 两种撤销都不能远程删除玩家已经下载的文件。

“最近联系”只表示设备上次请求管理服务的时间，不代表玩家在线。

## 术语速查

| 技术名称 | 界面中的含义 |
| --- | --- |
| Server | 一份服务器配置，组织清单和授权 |
| Artifact | 文件库中的 MOD JAR |
| Release | 搭配好的一版 MOD 环境 |
| Draft | 可以反复修改的草稿 |
| Published | 已封存，内容不可改；还需要启用 |
| Channel / stable | 分发通道 / 默认正式版，指向玩家应使用的版本 |
| required / optional / forbidden | 必须安装 / 玩家自选 / 禁止安装 |
| Mod ID | 作者定义的内部名称，可能不同于文件名和显示名称 |
| SHA256 | 文件指纹，自动计算和验证，无需手动填写 |
| Profile | 玩家客户端为服务器保存的地址和个人选择 |
| 签名公钥 | 客户端验证清单来源的公开信息，不是密码或邀请码 |

## 常见问题

**玩家打不开分享地址。** 检查服务端配置 `server.public_base_url` 是否为玩家能访问的地址，以及反向代理、TLS 和端口。`localhost` 只适合本机测试。修改部署配置后重启服务。

**上传成功，玩家却没有更新。** 检查文件是否已加入环境版本、这一版是否已封存、是否已启用到正式版。之后玩家需要主动检查同步并重启游戏。

**MOD 选择器中没有我刚传的文件。** 查看文件详情中的适用位置。仅服务端 MOD 和 Mod List Discovery 本身不会出现在客户端文件选择器中。

**封存失败。** 页面会给出解释，并提供可展开的检查详情。检查游戏版本要求、MOD 适用环境、依赖冲突和文件存储。不要为了跳过错误直接修改数据库。

**不知道校验码和签名怎么填。** 不需要手动填，系统会自动处理。高级详情用于排障。

**忘记管理员密码。** 在运行服务的机器使用 `mod-list-discovery-server admin set-password --config 配置路径`，交互输入新密码；至少 12 字节。重置会注销所有管理员会话。玩家无需管理员账号。

**页面显示网络错误。** 检查网络后重新尝试。表单提交失败会保留已填内容；不要把失败提示当作保存成功。登录过期需要重新登录。
