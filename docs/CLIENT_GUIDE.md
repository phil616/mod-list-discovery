# 玩家安装与同步指南

[文档首页](README.md) · [服主指南](ADMIN_GUIDE.md) · [官方安装资料](REFERENCES.md)

## 安装要求

| 项目 | 当前支持范围 |
| --- | --- |
| Minecraft | 针对 26.2 构建和验证；元数据声明 `~26.2` |
| Java | 25 或以上 |
| Fabric Loader | 声明最低 0.19.0，已验证 0.19.5 |
| Fabric API | 另行安装匹配 26.2 的版本；已验证 0.155.2+26.2 |
| Mod List Discovery | 下载 `mod-list-discovery-<版本>+mc26.2.jar` |

这不是全 Minecraft 版本通用 JAR，也不是 Forge / NeoForge MOD。服务端的 Linux 二进制不放进游戏 `mods/`。

先创建或选择匹配版本的 Fabric 游戏实例，再将客户端 JAR 与 Fabric API 放入该实例的 `mods/`。同一个 MOD 不要同时放入多个版本。游戏启动后在标题界面打开 **Mod List Discovery**。

## 首次加入

1. 向服主索取完整同步地址，例如 `https://mods.example.com/friends`。它不同于多人游戏服务器 IP。
2. 添加地址，系统为它创建本地环境配置（Profile）。私密服务器通过“设备授权”输入邀请码。
3. 检查环境：客户端验证清单签名、Minecraft / Loader / Java 版本并扫描本地 MOD。
4. 阅读同步计划，选择可选 MOD；对于未知的本地冲突文件，按提示决定是否隔离。
5. 确认同步。所有下载通过大小和 SHA256 校验后，才会修改 MOD 目录。
6. 退出并重启游戏，再次检查就绪状态，然后使用 Minecraft 游戏服务器地址联机。

只有本机开发地址 localhost / 127.0.0.1 / ::1 可以使用 HTTP；远程服务应使用 HTTPS。

## 必装、自选、禁止与重启

- 必须安装：服主指定的文件版本会进入同步计划。
- 玩家自选：可决定是否安装，首次选择可以由服主设置默认值。
- 禁止安装：命中指定 Mod ID 和版本范围时需要处理冲突。
- 需要重启：文件已经改变，但当前游戏仍运行旧的类；不能当作环境已经就绪。

同步工具不会替你升级 Minecraft、Loader、Java 或它自身。运行环境不匹配时，请先在启动器中调整。

## 多服务器与本地数据

多个 Profile 共享当前游戏实例的一个 MOD 目录，一次只有一个活动环境。应用同步计划会切换活动 Profile，切换时重新计算差异。移除非活动 Profile 不会删除它曾安装的所有 JAR。

数据在 `<gameDir>/mod-list-discovery/`，包括环境配置、受管理文件状态、临时下载、隔离目录和恢复日志；如果设置了 `fabric.modsFolder`，MOD 操作遵循该目录。

建议在重大 MOD 更新前备份游戏实例和世界存档。隔离文件可在客户端查看和恢复；恢复不会覆盖已有文件或制造同一个 Mod ID 的冲突。

## 常见故障

| 现象 | 处理方式 |
| --- | --- |
| 没有标题入口 | 检查是否启动正确的 Fabric 实例、JAR 是否放对目录、Fabric API 是否安装 |
| 游戏 / Java / Loader 不匹配 | 在启动器修正版本，不要仅修改服主清单绕过提示 |
| 没有可用清单 | 让服主确认已封存并启用正式版，地址中包含正确服务器标识 |
| 邀请码不可用 | 可能过期、用完或撤销，请服主提供新码 |
| 已登记设备无权限 | 可能设备授权已撤销，需要重新登记 |
| 服务器身份发生变化 | 与服主核实签名密钥是否更换，再在“服务器身份”明确确认重新信任 |
| 下载校验失败 | 重试并联系服主检查文件存储；不要手工绕过哈希校验 |
| 恢复模式 | 先通过客户端恢复或回滚未完成事务，再继续同步 |
| 只读模式 | 检查是否有另一个游戏实例正在操作同一个 MOD 目录 |

客户端凭证保存在仅当前用户可读的本地配置文件中，不应分享整个 Profile 文件。排障时可以提供错误信息和版本号，避免贴出邀请码、访问令牌或私钥。
